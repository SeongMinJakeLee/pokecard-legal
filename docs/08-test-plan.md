# 08. 테스트 계획

관련 문서: [02 기능](02-functional-spec-and-scenarios.md) · [05 API](05-api-spec.md) · [07 보안](07-error-handling-and-security.md) · [09 개발 계획](09-development-plan.md)

> 테스트 도구는 DEC-01/02 확정 후 선택한다. 이 문서는 **전략, 범위, 케이스, 합격 기준**을 정의한다.

## 1. 테스트 목표
1. P0 기능(FR)이 인수 기준(02 문서 §4)을 충족함을 증명한다.
2. 보유 데이터의 **정확성/격리/동기화**(핵심 가치)를 보장한다.
3. 외부 API 의존 부분(동기화)을 **장애 상황에서도 안전**하게 만든다.
4. 스토어 출시에 필요한 품질·보안·정책 요건을 확인한다.

## 2. 테스트 전략 (피라미드)

| 레벨 | 대상 | 비중 | 자동화 |
|------|------|------|--------|
| 단위(Unit) | 순수 로직: 검증, 커서 인코딩/디코딩, 정렬키 변환, `hp`/`number` 파싱, 어댑터 변환, 필터 조합 | 높음 | 자동 |
| 통합(Integration) | API + 실제 DB(테스트 DB): 쿼리, 제약, 인증, 보유 격리, 동기화 upsert | 높음 | 자동 |
| 계약(Contract) | OpenAPI 스펙 ↔ 실제 응답/클라이언트 타입 일치 | 중 | 자동 |
| 컴포넌트/UI | 화면 상태(로딩/빈/오류), 토글 낙관적 업데이트·롤백 | 중 | 자동 |
| E2E | 가입→목록→검색→보유→재실행 등 핵심 시나리오 (에뮬레이터/실기기) | 낮음(핵심만) | 자동+수동 |
| 비기능 | 성능, 보안, 호환성, 접근성 | 필요 시 | 일부 자동 |
| 수동 탐색 | 실기기, UX 점검 | 릴리스 전 | 수동 |

## 3. 테스트 환경
| 항목 | 내용 |
|------|------|
| 테스트 DB | 케이스마다 격리되는 별도 DB(마이그레이션 적용) |
| 외부 API | **Mock/녹화 응답(fixture)** 사용. 실제 API 호출은 별도 수동/야간 스모크에서만 |
| 시드 데이터 | 소규모 카드/세트 세트(트레이너·에너지·포켓몬, 다중 타입, HP 없음, 번호 `TG01` 형태 등 경계 사례 포함) + 대규모 데이터셋(성능용, 약 2만 장 규모) |
| 기기 | Android 에뮬레이터 + 실기기(저사양/중급/고사양 각 1대 이상) |
| CI | 변경 시 단위/통합/계약 자동 실행 (Phase 1에서 구성) |
