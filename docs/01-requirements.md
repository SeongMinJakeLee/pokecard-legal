# 01. 요구사항 정의서

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | 임시 표시명 **pokecard**. 스토어/런처 최종 이름은 나중에 정함. 내부 Supabase 프로젝트명은 `card-dex` |
| 목적 | 포켓몬 TCG 카드를 전체 조회하고, 내가 가진 카드를 체크해 보유 현황을 관리한다 |
| 성격 | 포트폴리오 겸 실서비스 (앱 스토어 출시 목표) **[확정]** |
| 대상 사용자 | 포켓몬 카드를 수집하는 일반 사용자 (여러 명이 각자 계정으로 사용) **[확정]** |
| 핵심 가치 | "전체 카드 도감 + 내 보유 표시" 를 빠르고 간단하게 |

## 3. 범위

### 3.1 포함 (In Scope — MVP, P0)
- 회원가입 / 로그인 / 로그아웃 / 세션 유지 / 회원 탈퇴
- 영문판 포켓몬 카드 전체 목록 조회 (무한 스크롤)
- 이름 검색, 세트·타입·희귀도 필터, 정렬
- 카드 상세 조회
- 보유 카드 체크/해제 (계정 단위 서버 저장, 기기 간 동기화)
- 보유/미보유만 모아 보기
- **위시리스트**: 갖고 싶은 카드 추가/제거와 위시리스트 목록 조회 (로그인 전용)
- 비로그인 사용자의 로그인 전용 기능 접근 시 로그인 화면 이동·복귀 (FR-GATE-01)
- 회원가입 연령 확인 (만 14세 이상만 가입)
- 외부 카드 데이터를 자체 서버 DB로 동기화하는 운영 기능
- Android 앱 (Google Play 출시)

### 3.2 확장 예정 (P1 — MVP 직후) **[제안]**
- (위시리스트는 사용자 결정으로 **MVP(P0)에 포함**되어 §3.1로 이동. 별도 즐겨찾기(★)는 만들지 않음)
- 시세 조회 (카드 상세에 표시)
- 한글 이름 검색 (포켓몬 도감번호 → 한글명 매핑, DEC-10)
- 비밀번호 재설정 / 소셜 로그인 (DEC-04 결과에 따라 — 이메일 방식이면 출시 전 필수)

### 3.2.1 보류 (요구가 생기면 검토)
- 세트별 수집 진행률 (사용자 결정: 중요하지 않음, 2026-10-07)

### 3.3 장기 / 조사 필요 (P2) **[제안]**
- 카드 스캔 (카메라 인식)
- 한글판 카드 데이터 (DEC-09)
- 다국어 UI
- 웹 클라이언트
- 보유 수량/상태/버전/메모 확장
- iOS (DEC-12)

### 3.4 제외 (Out of Scope, 현재)
- 카드 거래/마켓, 소셜 기능(친구, 공유)
- 덱 빌딩 (사용자가 언급한 후보 기능에 없으므로 현재 제외. 필요 시 추후 요구사항으로 추가)
- 카드 게임 플레이/배틀 기능
- 관리자용 웹 콘솔 (동기화는 서버 배치 작업으로 처리)

## 6. 제약 조건 및 가정

### 6.1 제약
| ID | 제약 | 영향 |
|----|------|------|
| C-01 | 외부 데이터 소스 **(4차)**: 개발·1차 출시는 **무료**인 [Pokémon TCG API](https://docs.pokemontcg.io/) v2 및/또는 JSON 덤프. API 키 있음 20,000건/일. **이 API는 폐기 예정이며 2027-03-01 종료**. 유료 Scrydex는 쓰지 않음. 앱은 소스를 직접 호출하지 않고 **운영자가 적재한 Supabase DB만 조회** | 어댑터 계층 유지. 종료일 전 후속 소스 재결정 (DEC-16 잔여) |

## 8. 용어 정의

| 용어 | 정의 |
|------|------|
| 카드(Card) | Pokémon TCG API의 card 객체 단위. 고유 `id`(예: `swsh4-25`) |
| 세트(Set) | 카드가 속한 확장팩 (예: Vivid Voltage). 고유 `id`(예: `swsh4`) |
| 보유(Owned) | 사용자가 해당 카드를 가지고 있다고 체크한 상태 |
| 동기화(Sync) | 외부 API 데이터를 자체 DB로 가져와 갱신하는 서버 작업 |
| MVP | 1차 출시 최소 기능 집합 (P0) |
