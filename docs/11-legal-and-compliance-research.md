# 11. 법적·정책 조사 결과 (지식재산권, 데이터 소스, 광고·아동, 스토어)

조사일: 2026-10-07
관련: [01 R-01/R-06](01-requirements.md) · [07 §3·§4](07-error-handling-and-security.md) · [README DEC-13/14/16/17](README.md)

> **이 문서는 법률 자문이 아니다.** 공개된 정책/약관 원문을 조사해 정리한 것이며, 출시(특히 광고 포함 상업 출시) 전에는 변호사/변리사 자문을 받는 것을 권장한다. 아래 "미확인" 항목은 원문을 확인하지 못했거나 조사 범위 밖이다.

### 1.2 해석 (설계에 미치는 영향)
- **허가를 받을 수 있는 공개 라이선스/팬 콘텐츠 가이드라인이 확인되지 않았다.** 앱이 상업적(광고 포함)이면 카드 이미지·카드명·포켓몬 이름 사용이 침해로 주장될 위험이 높다.
- 데이터 제공사가 이미지를 제공하더라도 **그것이 IP 사용권을 부여하는 것은 아니다.** (예: 다른 카드 API 약관도 "이미지 사용이 허용되는지는 개발자 책임"이라고 명시)
- **리스크 수준은 사용 방식에 따라 다르다:**

| 방식 | 위험 | 비고 |
|------|------|------|
| A. 광고/유료 + 카드 이미지·이름 사용 + 스토어 상업 출시 | **높음** | 현재 구상. 신고 시 삭제 가능성 |
| B. 광고/유료 없음(무료·비영리) + 이미지·이름 사용 + 스토어 출시 | 중~높음 | 비상업이어도 스토어 정책·권리자 신고 위험은 남음 |
| C. 이미지 없이 텍스트 데이터만(이름 표기는 식별 목적) | 중 | 카드 "도감"의 가치가 크게 떨어짐. 이름 상표 이슈는 남음 |
| D. 포트폴리오로 코드/데모만 공개하고 스토어 출시는 하지 않음 | 낮음 | 출시 목표와 상충 |
| E. 권리자에게 서면 허가 획득 후 A | 낮음 | 권리자가 검토하지 않는다고 밝혀 현실성이 낮음 |

### 1.3 권장 사항 (사용자 결정 필요 → DEC-13)
1. 출시 전 **지식재산권 전문 변호사/변리사 자문** (한국·미국·일본 등 배포 국가 기준)
2. 최소 위험을 위한 완화책 (위험이 없어지지는 않음)
   - 앱 이름/아이콘/스토어 설명에 포켓몬 상표·로고·공식 이미지 사용 금지, 앱 이름에 "Pokémon" 포함 금지
   - "비공식 팬 앱이며 The Pokémon Company, Nintendo 등과 무관" 고지
   - 광고·유료화 보류 또는 단계적 접근 (처음 출시는 무광고 무료)
   - 신고 접수 시 신속 삭제 대응 절차(이미지 제거 가능한 설계 — 이미지를 표시 전용 외부 URL로 두는 방식이 이 점에서는 유리)
   - 출시 국가를 한국으로 한정해 법적 범위를 줄임 (IP 자체의 위험이 없어지지는 않음)
3. 스토어 출시를 포기하지 않는 경우에도, 비상업 포트폴리오(웹 데모/소스 공개)와 상업 출시는 **분리해서 판단**

### 1.4 미확인
- 한국 상표법·부정경쟁방지법·저작권법에 따른 구체적 판단 (조사하지 않음, 자문 필요)
- 포켓몬코리아/The Pokémon Company 별도 라이선스 프로그램 존재 여부 (공개 자료에서 확인되지 않음)

## 2. 카드 데이터 소스 (설계 전제 변경)

### 2.1 Pokémon TCG API 폐기 예정 (원문 확인)
출처: [PokemonTCG/pokemon-tcg-data README](https://github.com/PokemonTCG/pokemon-tcg-data) (원문 직접 확인)
- "Pokémon TCG API는 레거시이며 신규 연동에 권장하지 않는다."
- "**Pokémon TCG API는 2027년 3월 1일에 오프라인으로 전환될 예정**"
- 후속: **Scrydex** (https://scrydex.com). Scrydex 문서도 "Pokémon TCG API(이전 pokemontcg.io)의 발전형"이라고 소개한다.
- 기존 JSON 데이터 저장소(`pokemon-tcg-data`)는 **과거 데이터로 남지만 신규 앱의 기본 소스로 쓰지 말 것**을 권고하며 갱신은 중단 방향이다.

> 따라서 01~10 문서에서 "Pokémon TCG API v2"를 쓴 부분은 **현 시점 기준 임시 가정**이며, 출시(2027년 초 이후 가능성)와 겹치므로 **DEC-16으로 소스를 새로 결정**해야 한다. (ADR-01 "서버 DB 동기화"와 ADR-03 "어댑터 계층"은 소스가 바뀌어도 유효하며, 오히려 이 상황을 대비한 설계다.)

### 2.2 후보 비교

| 후보 | 확인된 사실 | 장점 | 단점/미확인 |
|------|-------------|------|-------------|
| **Scrydex** | 유료 요금제(Starter $29/월 5,000 크레딧, Growth $99/월 50,000 크레딧 등). 요청 대부분 1 크레딧. 영어/일본어 카드 지원, **한국어는 로드맵**. 카드/세트/시세/가격 이력/이미지 인식(스캔 후보 기능, 5 크레딧) 제공 | 유지보수됨, 시세·스캔 기능과 연결 가능, 한국어 지원 예정 | **월 비용 발생**, 약관(상업 이용, 이미지 표시, 데이터 저장/캐시 범위) **미확인**, 한국어 시점 미정 |
| 기존 Pokémon TCG API 계속 사용 | 현재 무료(20,000/일), 2027-03-01 종료 | 당장 개발 가능, 무료 | **출시 직후 종료** 위험. 신규 세트 갱신 중단 가능성 |
| 기존 데이터 저장소(JSON 덤프) 1회 가져오기 | 과거 카드는 확보 가능 | 무료, 안정적 | **신규 세트 갱신 없음**, 시세 없음 |
| 기타 제3자 API (예: pokemontcgapi.com, CardDex 등) | 상업 이용 허용을 명시한 곳도 있으나 이미지 저장·미러링 금지, 이미지 URL 만료 등 조건 상이 | 대안 존재 | 신뢰성/지속성/약관 개별 검증 필요 (이번 조사에서 상세 검증하지 않음) |

### 2.3 설계 시사점
- 사용자 구상(서버 DB에 복사)은 **소스 약관이 "대량 데이터 재배포/미러링/이미지 일괄 다운로드"를 금지하는지**에 따라 제한될 수 있다. 일반적으로는 자기 앱 내부 사용 목적의 캐시는 허용하나 **소스별 약관 확인이 필수**다 (Scrydex 약관 미확인).
- **이미지는 DB로 복사하지 않고 소스가 제공하는 URL을 표시만 하는 방식**이 약관·IP 양쪽에서 안전한 쪽이다 (DEC-05 기본안 유지 근거 강화).
- 비용: 데이터 소스(유료 가능) + Supabase 유료 플랜이 **광고 수익 없이도 월 고정비**가 될 수 있다 (NFR-COST-01 재검토).
- 한글판(P2): Scrydex 한국어 지원 로드맵과 연계 가능 (DEC-09).

### 2.4 권장 진행 순서 (제안)
1. Scrydex 약관·요금·데이터 필드·한도·이미지 정책 원문 확인 (PH-0 T-001 확대)
2. 개발 초기에는 소스 어댑터를 인터페이스로 분리해 두고, 무료인 기존 API(종료 전까지)나 JSON 덤프로 개발 → 출시 전 소스 최종 결정
3. 출시일이 2027-03-01 이전이면 소스 이전 계획, 이후이면 처음부터 후속 소스로 연동

## 3. 광고와 전연령 대상 (Google Play 가족 정책)

### 3.1 확인된 내용 (원문 근거)
출처: Play Console Help — [Target audience and content](https://support.google.com/googleplay/android-developer/answer/9867159), [Google Play Families Policies](https://support.google.com/googleplay/android-developer/answer/9893335), [Data practices in Families apps](https://support.google.com/googleplay/android-developer/answer/11043825), [Families Self-Certified Ads SDK Program](https://support.google.com/googleplay/android-developer/answer/9900633)

- 대상 연령에 **아동이 하나라도 포함**되면(전연령 포함) 가족 정책 요건을 준수해야 한다.
- 아동 및 연령 미확인 사용자에게는 **Families Self-Certified Ads SDK로만 광고**를 표시해야 하며, **맞춤형(관심 기반) 광고/리마케팅 금지**.
- 아동과 성인 모두 대상인 앱은 **중립적 연령 확인 화면(neutral age screen)** 을 구현해, 연령 확인으로 성인임이 확인된 사용자에게만 비인증 SDK 광고를 허용할 수 있다.
- 아동 대상 가능 앱은 **앱 시작 시 광고 ID(AAID)를 전송하지 않아야 하며**, 성인임이 확인된 후에만 가능하다.
- 아동 포함 앱은 **승인되지 않은 SDK/API를 통해 로그인하게 하거나 콘텐츠에 접근하게 해서는 안 된다**(Families Policy Requirements).
- 인증 광고 SDK 프로그램은 **현재 신규 신청을 받지 않으며**, 기존 인증 SDK 버전만 사용 가능하다. (사용 가능한 SDK 목록은 출시 시점에 확인)
- 구글은 "아동과 성인을 모두 대상으로 한다는 선택은 **실제로 모든 연령을 위해 설계된 경우에만**, 단지 배포 범위를 넓히려는 목적이면 안 된다"고 안내한다. 포켓몬 카드는 아동에게 어필하는 콘텐츠여서 **아동 대상(child-directed)으로 분류될 가능성**이 있다.

### 3.2 영향
- "전연령 + 광고"를 유지하려면 다음이 필요: (1) 대상 연령 선언 및 가족 정책 준수, (2) 연령 확인 화면, (3) 인증된 광고 SDK 또는 광고 미표시, (4) 개인정보처리방침의 정확한 기재, (5) 광고/분석 SDK 선택 제약 (DEC-15 크래시/분석 도구도 영향)
- 대안 (사용자 결정, DEC-17):

| 옵션 | 내용 | 영향 |
|------|------|------|
| 1 | 출시 시 **광고 없음**, 대상 연령은 전연령 유지 | 가족 정책 요건 중 광고 부분 회피, 개인정보·연령 정책은 여전히 필요 |
| 2 | **대상 연령을 청소년·성인(예: 13세 또는 14세 이상)** 으로 설정, 광고 허용 | 구글 요건 완화. "전연령" 요구와 달라짐. 아동이 실제로 쓸 수 있는 점은 별도 고려 |
| 3 | 전연령 + 광고, 연령 확인 + 인증 SDK 사용 | 기능 요건 증가, 광고 수익 감소 가능 |

- 만 14세 미만 아동의 개인정보를 처리하려면 **법정대리인의 동의**를 받고 **동의했는지 확인**해야 한다.
- 확인 방법 예: 법정대리인의 휴대전화 문자메시지/본인인증, 서면, 전자우편 회신 등. **아동이 직접 "부모 동의" 체크하는 것만으로는 부족**하다.
- 법정대리인 이름·연락처는 동의 확보를 위해 아동에게서 직접 수집 가능. 동의가 확인되지 않으면 수집 정보를 파기해야 한다.
- 아동에게 개인정보 처리 안내 시 이해하기 쉬운 양식과 명확한 언어를 사용해야 한다.

### 4.2 영향과 제안
- "전연령 + 이메일 회원가입" 조합은 **만 14세 미만 가입 시 법정대리인 동의 절차가 필요**해 구현 부담이 크다.
- **채택됨 (사용자 확정, 2026-10-07): "만 14세 미만은 게스트로만, 가입은 만 14세 이상".** 출시 국가는 한국. 아래는 그 근거와 세부안:
  - 회원가입에 **생년월일/연령 확인**을 두고 **만 14세 미만은 가입 불가, 게스트 열람만 허용**한다. 사용자가 이미 정한 "비로그인 열람/검색 전체 허용" 설계와 잘 맞고, 별도 법정대리인 동의 체계 구축을 피할 수 있다.
  - 이 경우 "전연령"은 **열람 기능은 전연령, 계정 기능은 만 14세 이상**으로 정의된다.
  - 연령 확인 화면은 구글의 neutral age screen 요건(정답을 유도하지 않는 방식)과 함께 설계한다.
- 해외 배포 시 미국 COPPA, EU GDPR 아동 규정 등이 추가될 수 있다 → **출시 국가를 한국으로 한정**하는 것을 권장(미조사 항목).

## 5. Google Play 스토어 정책 (IP·사칭)

출처: Play Console Help — [Intellectual Property](https://support.google.com/googleplay/android-developer/answer/9888072), [Impersonation](https://support.google.com/googleplay/android-developer/answer/9888374)
- 앱과 스토어 등록 정보의 모든 콘텐츠는 **본인 저작물이거나 필요한 라이선스/허가가 있어야** 한다. 서면 허가가 있으면 제출 전에 구글 팀에 사전 연락을 권장한다.
- "원작과 구별되지 않는 팬 아트/복제"는 위반 예시에 포함된다. 저작물을 **수정해도** 위반일 수 있다. 개발자가 **권리 사용 증빙**을 요구받을 수 있다.
- **사칭 금지**: 앱 제목·아이콘·설명이 타 기업/앱과 관련 있는 것처럼 오인하게 하면 안 된다. "비공식"이라는 표기만으로 무단 브랜딩이 허용되지는 않는다.
- 권리자는 저작권/상표 신고 양식으로 신고할 수 있고, 위반 시 앱 제거와 **개발자 계정에 대한 조치** 대상이 될 수 있다.

## 7. (3차 추가) "스토어에 포켓몬 카드 앱이 많은데 저작권에 안 걸리나?" + 광고 출시 검토

### 7.1 결론
**많이 있다는 사실만으로는 합법이라고 볼 수 없다.** 확인할 수 있는 것은 "현재 노출되어 있다"뿐이고, 그 앱들이 라이선스를 받았는지, 신고를 받았는지, 법적으로 허용되는 방식인지는 **공개 자료로 확인되지 않는다.** 따라서 이 사례는 "위험이 낮다"는 근거가 아니라 "단속이 일률적이지 않다"는 관찰 정도로만 쓴다.

### 7.2 확인된 사실과 해석
| 구분 | 내용 | 신뢰도 |
|------|------|--------|
| 사실 | 포켓몬 측은 IP 사용 요청을 검토하지 않고 프로젝트에 사용하지 말 것을 요청한다 (§1.1) | 공식 문서 |
| 사실 | 스토어의 카드 스캐너/컬렉션 앱 다수가 스스로 "비공식(unofficial)"이며 포켓몬 측과 무관하다고 고지한다 | 스토어 목록 관찰 |
| 사실 | 2011년경 포켓몬 측이 안드로이드 마켓의 포켓몬 앱들에 저작권 침해 삭제 요청(DMCA)을 보내 다수 앱이 내려간 사례가 보도·포럼에 있다 | 언론/커뮤니티 보도 (1차 문서 미확인) |
| 사실 | Google Play는 권리자 신고 시 앱 삭제와 개발자 계정 조치가 가능하다 (§5) | 공식 정책 |
| 해석 | 현재 앱들이 남아 있는 것은 **권리자가 선택적으로 집행**하거나 아직 신고가 없기 때문일 수 있다. 허가를 받았다는 증거는 없다 | 추정 |
| 해석 | "비공식" 고지는 **사칭(오인) 위험을 낮추는 효과는 있어도 침해 책임을 면하게 하지 않는다**. 스토어도 같은 입장 (§5) | 정책 원문 + 일반 법리, 자문 필요 |
| 해석 | 광고·유료화가 붙으면 비상업 이용보다 **상업적 이용으로 보일 가능성**이 커진다. 2011년 사례도 유료 앱이 먼저 표적이 되었다는 보도가 있다 | 추정 |
| 해석 | 일부 국가에는 인용·참조 목적 예외가 있으나 **국가별로 다르다.** 한국 저작권법에도 공표된 저작물의 인용 규정이 있으나, 광고 포함 상업 앱이 카드 이미지를 대량 표시하는 경우에 적용되는지는 **사안별 판단이라 자문이 필요**하다 | 일반 정보, 미조사 |

### 7.3 한국 한정 출시에서의 현실적 경로
- **포켓몬코리아 이용약관 제12조**: 콘텐츠의 영리적 이용은 **회사와 사전 협의**가 필요하다고 규정한다. 공개된 문의처는 webmaster@pokemonkorea.co.kr, 1588-4273이다. 이 약관은 해당 사이트의 콘텐츠에 대한 것이라 우리 앱에 직접 적용되는지는 불명확하지만, **한국 한정 출시라면 한국 법인에 직접 문의하는 것이 가장 현실적인 허가 경로**다. (글로벌 지원 문서는 "검토하지 않는다"고 하나 한국 법인의 입장은 확인되지 않음)
- 문의 시 질문 예: 비공식 도감/수집 관리 앱, 카드 이미지·이름 표시, 광고 포함 여부별 허용 가능성.
- 서면 답변을 받으면 Google Play 권리 증빙으로도 활용 가능 (§5).

### 7.4 광고 포함 출시: 선택지와 설계 영향
| 안 | 내용 | 장점 | 위험/비용 |
|----|------|------|-----------|
| A | **무광고 1차 출시** → 반응 확인·포켓몬코리아 회신 후 광고 도입 | IP 위험 최소화, 가족 정책 광고 요건 보류 | 초기 수익 없음. 월 고정비(Supabase Pro 등)는 발생 |
| B | 포켓몬코리아에 **사전 문의 후** 결과에 따라 광고 여부 결정 | 허가/거절을 근거로 판단 가능 | 회신 시간, 거절 가능성 |
| C | **광고 포함 즉시 출시** | 수익 즉시 | 신고 시 삭제·개발자 계정 불이익(포트폴리오 목적에도 타격), 가족 정책 준수 필요 |

- **완화 설계(어느 안이든 유효)**: (1) 앱 이름·아이콘·스토어 문구에 포켓몬 상표/로고 미사용, (2) 이미지는 서버 설정 하나로 **즉시 숨길 수 있는 원격 스위치** 설계, (3) 신고 대응 절차 문서화, (4) 한국 한정 배포.
- **가족 정책과 광고(출시 전 확인 필요)**: 대상이 전연령이면 연령 미확인 사용자(게스트)에게는 인증 SDK 광고만 허용된다 (§3.1). **만 14세 이상이 확인된 로그인 사용자에게만 광고를 표시하고 게스트에게는 광고를 노출하지 않는 방식**이 단순한 후보지만, 구글 정책상 이 방식이 중립 연령 확인 요건을 충족하는지는 **미확인**이다 (PH-0 T-013에서 정책 원문 확인). 또한 구글이 "아동"으로 보는 연령 기준이 한국에서 만 14세와 일치하는지도 확인 대상이다.
- **채택됨 (4차)**: 안 **A. 1차 출시 무광고**. 광고 도입은 이후 별도 결정. 아래 B/C는 이력.
